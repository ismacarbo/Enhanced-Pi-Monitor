Robotics Platforms

This page collects the robotics platforms I build and iterate on. The common direction is always the same: robust embedded control, clean telemetry, and practical autonomy that can be debugged quickly.

RedPanda4x4

4WD rover platform focused on wireless teleoperation, deterministic fallback behavior, and fast field tests.

RedPanda4x4 is built around an ESP32 architecture with a split TX/RX control path and low-latency link. It supports both manual driving and assisted autonomous reactions, making it ideal for validating control logic, recovery strategies, and sensor placement before moving to heavier stacks.

  • Control: ESP32 TX/RX setup, joystick/command modes, emergency stop pipeline.
  • Locomotion: 4x4 differential drive tuned for traction and curb/slope tolerance.
  • Perception-ready: camera stream support and interfaces designed for CV modules.
  • Use case: rapid prototyping for outdoor navigation and autonomy experiments.

BotFusion

Autonomous robot framework that combines embedded telemetry, LiDAR integration and occupancy mapping.

BotFusion is the bridge between low-level robot control and high-level software observability. It streams compact robot telemetry, fuses sensing data, and builds a rolling map that can be inspected in real time. The focus is clarity: every subsystem is readable, measurable, and replaceable.

  • Core stack: Arduino control loop + Raspberry Pi processing/runtime services.
  • Sensing: IMU + distance sensors + LiDAR ingest for local environment understanding.
  • Mapping: rolling occupancy grid with hit/free updates and lightweight persistence.
  • Debug UX: live dashboard with state machine status, telemetry and map overlays.

Autonomous Robot Platform (Enhanced Pi Monitor)

Integrated monitoring and control environment for robot experiments on Raspberry Pi.

This platform extends the robotics stack with operations tooling: API endpoints, live streams, telemetry ingestion, alerts, and on-device services to monitor system health while the robot is running.

  • System: Flask backend with modular routes for robot and sensor APIs.
  • Monitoring: CPU, memory, disk, voltage and network metrics for runtime diagnostics.
  • Integration: links robotics data, automation utilities and safety alerts.
  • Goal: keep robot experiments observable, reproducible, and easy to iterate.
